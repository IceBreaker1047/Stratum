# Stratum

Stratum is a local PDF parsing pipeline for extracting clean, structured chunks from academic and technical documents. It reads a PDF, removes common bleed-through content like repeated headers and footers, builds a semantic tree of the document, flattens that tree into retrieval-friendly chunks, and adds a lightweight RAG score to each chunk before writing the result to JSON.

## What It Produces

The final output is a list of chunks in `final_database_chunks.json`. Each chunk typically includes:

- `type`
- `content`
- `h1_context`, `h2_context`, `h3_context` when available
- `html` for table chunks and `table_data` when structured rows are available
- `rag_score`
- `rag_metrics`

## Features

- PDF text extraction with bleed filtering
- Multi-column aware reading order
- Heading detection and semantic hierarchy building
- Table extraction with structured row handling
- Image preservation with optional base64 payloads
- Chunk flattening with heading context carried forward
- Post-processing validation and RAG score assignment

## Running the Pipeline

The current entry point is the local script in `Parser/main.py`.

```bash
python Parser/main.py
```

By default this reads `Sample_PDFs/research2.pdf` and writes the output to `final_database_chunks.json`.

If you want to call the pipeline from another script:

```python
import sys
sys.path.insert(0, "Parser")

from main import process_pdf_to_database

chunks = process_pdf_to_database(
    "Sample_PDFs/research2.pdf",
    "final_database_chunks.json",
)
print(len(chunks))
```

## Pipeline Flow

1. `extract_without_bleeds()` in `Parser/bleeder.py` extracts page elements and filters repeated margin content.
2. `construct_semantic_tree()` in `Parser/tree.py` groups the extracted content into a hierarchical structure.
3. `flatten_tree_to_chunks()` converts the tree into linear chunks and carries heading context into each chunk.
4. `process_chunks_validation()` in `Parser/validation.py` assigns `rag_score` and `rag_metrics`.
5. `Parser/main.py` writes the validated chunks to JSON.

## Output Notes

- Table chunks keep their extracted table text, and may also carry structured table rows when available.
- Image chunks keep the image description and `base64_image` when available.
- Newlines are normalized out of chunk content before saving.
- Bbox and page metadata are intentionally not persisted in the final file.

## How It Works

### Bleed Filtering

The extractor scans the page margins and suppresses repeated content such as headers, footers, and page numbers. It also detects simple multi-column layouts so the extracted reading order stays usable.

### Semantic Tree

The tree builder uses font size and text structure to decide whether a line should become a heading or body paragraph. Tables and images are attached as dedicated leaf nodes instead of being treated as plain text.

### Chunk Flattening

The flattener walks the tree, carries heading context forward, and merges nearby text into stable chunk-sized blocks. It also keeps table and image chunks separate so they remain easy to retrieve later.

### Validation

Validation adds a compact quality score to each chunk:

- `integrity` favors sufficiently sized chunks
- `density` measures how information-rich the content is
- `rag_score` combines both into a single number

## Example Output Shape

```json
{
    "type": "paragraph",
    "h1_context": "Sample IEEE Paper for A4 Page Size",
    "content": "Address Including Country Name First Third Department, First Third University ...",
    "rag_score": 0.574,
    "rag_metrics": {
        "score": 0.574,
        "integrity": 1.0,
        "density": 0.29
    }
}
```

A table chunk looks similar to this:

```json
{
    "type": "table",
    "h1_context": "Sample IEEE Paper for A4 Page Size",
    "content": "| Font Size | Appearance ...",
    "html": "| Font Size | Appearance ...",
    "table_data": [],
    "rag_score": 0.922,
    "rag_metrics": {
        "score": 0.922,
        "integrity": 1.0,
        "density": 0.87
    }
}
```

## Notes

- `final_database_chunks.json` is generated output and can be regenerated by rerunning the pipeline.
- The sample PDF in `Sample_PDFs/` is the default input used by `Parser/main.py`.
- The repository is currently centered on the parser pipeline rather than a live web API.
